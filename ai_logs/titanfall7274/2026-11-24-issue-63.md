### 1. 키보드 종료 시 변경 입력 분석

- 프롬프트: 한글을 입력하는 동안 분석을 기다리고 키보드를 내렸을 때 변경된 입력만 분석한다.
- AI 응답: 작성 화면에서 키보드 높이와 분석 문자열을 전달하고, 화면마다 모델 하나를 별도 isolate에서 실행한다. isolate는 화면을 그리는 코드와 별도로 Dart 코드를 실행하는 공간이다.
- 판단: 채택. 모델을 매번 준비하는 비용을 줄이고 분석 중에도 본문을 편집하거나 게시할 수 있다. 입력이 바뀌거나 화면을 닫으면 이전 응답을 버린다.

### 2. 점수와 추천 후보 표시

- 프롬프트: 시안의 8개 주제 막대에 실제 점수를 연결하고 추천 후보만 선택할 수 있게 한다.
- AI 응답: 모델 출력 순서를 막대에 유지하고 #27의 선정 함수를 후보에 적용한다. 키보드를 다시 열거나 점수를 접어도 직전 막대를 보존한다.
- 판단: 채택. 사전에 일치하는 글자 조각이 없어 추천을 생략한 경우에도 사용자가 실제 모델 점수를 확인할 수 있다.

### 직접 검증한 내용·결과

- 키보드 높이를 바꾸는 작성 화면 테스트에서 AI 영역이 숨었다가 다시 나타나는 동작과 후보 제거·재선택 후 게시를 확인했다. 막대 테스트에서는 100ms의 중간값과 200ms의 최종값을 비교했다.
- 독립 리뷰에서 마지막 분석 본문으로 편집을 되돌리면 다시 추론하는 경우를 발견했다. 완료 입력과 결과를 보관하도록 수정하고 ‘여행 → 여행지 → 여행’에서 추론이 한 번인지 검사했다.
- 최초 예약에서는 ADB 오류 10060으로 연결하지 못했다. 이후 USB 디버깅으로 S23(SM-S918N, Android 16, R3CW90M99JT)에 커밋 8377bfd의 APK를 설치했다.
- 삼성 한글 키보드에서 ‘오늘 도서관에서 시험 공부를 하고 과제를 마무리’를 자판으로 입력했다. 입력 중 AI 영역 숨김, 키보드 종료 뒤 공부 후보와 8개 점수 표시, 점수 접기·펼치기를 화면과 접근성 트리로 확인했다. 공부 점수의 화면 반올림 값은 1.00이었다.
- USB 연결을 유지한 채 비행기 모드를 켜고 본문 중간에 한글 자모를 추가한 뒤 키보드를 내렸다. 변경 입력에서도 공부 후보와 점수가 나타났다. 검증 후 비행기 모드를 원래 꺼진 상태로 복원하고 앱을 종료했다.
- 실기기의 정확한 추론 횟수·응답 시간·200ms 애니메이션 지속 시간은 계측하지 않았다. 동일 입력 재사용과 200ms 전환은 자동 검사 결과를 근거로 한다.

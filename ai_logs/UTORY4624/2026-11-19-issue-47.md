### 1. 게시글 페이지 조회와 작성 재시도 계약

- 프롬프트: #16 규칙과 PR #57을 기준으로 #47 저장소 인터페이스와 계약 테스트를 먼저 만들어 달라고 요청했다.
- AI 응답: 전체 조회를 쓰는 MP1 화면을 유지하면서, 작성 시각과 문서 ID를 기준으로 20개씩 조회하는 메서드를 추가했다. PR #57처럼 선택적인 요청 ID를 받고, ID가 주어지면 글 ID로 사용한다. 같은 ID·작성자·본문이면 최초 글과 작성 시각을 반환하고, 작성자·본문이 다르면 거부한다. 메모리 저장소와 테스트 대역을 이 계약에 맞췄다.
- 판단: 계약 초안에 반영. 화면에서 처리하기 쉬운 전체 조회는 기존 흐름에 유지하고, MP2 페이지는 이미 읽은 개수가 아니라 마지막 글의 시각과 ID로 이어서 읽는다. 항상 ID를 새로 생성하면 재시도 때 서로 다른 글이 될 수 있으므로, 요청 ID를 전달받는 방식으로 최초 글을 찾는다. 인터페이스 변경은 #13·#14 담당자 검토 대상으로 둔다.

후속 Firestore 구현에서는 `authorId`, `nickName`, `colorIndex`, `body`, `createdAt`, `likeCount`, `commentCount`를 #16 규칙에 맞춰 저장한다. `createdAt`은 서버 시각을 쓰고, 두 카운터는 정수 0으로 시작한다. 요청 ID는 문서 ID로 쓴다. 댓글 조회는 오래된 순이며, 빈 결과와 조회 실패를 구분한다.

### 자동 검증 결과

- 구현 전 계약 테스트 실행에서 페이지 조회 메서드와 요청 ID 이름 인자가 없다는 오류를 확인했다.
- 구현 후 저장소 단위 테스트 17개 통과. 45개를 20·20·5로 조회, 같은 시각의 페이지 경계, 꽉 찬 마지막 페이지, 동시에 같은 요청 ID로 재시도, 본문·작성자 충돌, ID 없는 각 요청의 별도 생성을 확인했다.
- Flutter 3.47.5 / Dart 3.13.4에서 `flutter test --no-pub`로 전체 113개 통과, 기존 1개 건너뜀. 동일한 잠금 파일을 쓰는 임시 복사본에서 `flutter analyze --no-pub` 문제 0건.
- 이번 검증 범위는 인터페이스와 메모리 저장소다. Firestore 구현체의 문서 변환, 서버 작성 시각과 동시 재시도, 앱 연결은 후속 검증이다.

### 2. Firestore 게시글·댓글 저장소 구현

- 프롬프트: 앞서 만든 #47의 인터페이스에 맞춰 게시글·댓글 저장소를 구현하고 #16 규칙이 적용된 에뮬레이터에서 검증해 달라고 요청했다.
- AI 응답: 게시글 문서의 작성 시각·ID로 20개씩 읽고, 작성 시 요청 ID에 해당하는 문서를 트랜잭션에서 확인해 처음 한 번만 만들도록 구현했다. 최초 서버 작성 시각을 읽어 결과로 반환한다. 댓글은 게시글 하위 경로에서 오래된 순으로 읽는다.
- 판단: 채택. 동일 요청이 동시에 들어와도 같은 문서에 대해 읽고 생성하므로 최초 글과 작성 시각을 유지할 수 있다. 게시글이 실제로 없거나 댓글 목록이 비어 있을 때는 빈 결과를 반환하고, 권한·연결 오류는 화면에서 구분할 수 있게 전달한다. 지금 단계의 조회는 서버를 기준으로 하고 오프라인 캐시 연결은 #15 범위로 둔다.

### 자동 검증 결과

- `tests/firestore/`에서 `npm run test:repositories`로 #16 규칙을 적용한 데모 Auth·Firestore 에뮬레이터와 Flutter SDK를 연결했다. 15개 통과. 익명 로그인, 45개 글의 20·20·5 페이지와 동률 경계, 없는 게시글 조회, 댓글 정렬과 빈 목록·권한·연결 오류, 필드 7개와 서버 작성 시각, 동시 재시도, 본문·작성자 충돌, 가족 이모지 300개 허용·301개 거부를 확인했다.
- Windows의 Flutter 3.47.5 웹 테스트 러너가 CanvasKit 요청을 404로 반환했다. 이번 실행에서는 해당 브라우저 요청에 설치된 Flutter SDK의 CanvasKit 파일을 공급해 테스트를 완료했다.
- 같은 규칙 파일로 다시 `npm test`를 실행해 Firestore 규칙 테스트 70개가 통과했다. `flutter test --no-pub`는 115개 통과, 기존 1개 건너뜀. 동일한 잠금 파일을 사용한 임시 복사본의 `flutter analyze --no-pub` 결과는 문제 0건이다.
- 현재 앱에서 구현체를 주입하고 화면·USB 실기기에서 확인하는 작업은 #13·#14 연결 범위다.

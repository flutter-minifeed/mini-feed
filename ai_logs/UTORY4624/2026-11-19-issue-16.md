### 1. 무료 Firestore 규칙의 게시글 300자 제한

- 프롬프트: Flutter가 보는 글자 300개를 유지하고 가족 이모지도 한 글자로 처리하는 무료 Firestore 검사를 검증한 뒤 게시글 생성 규칙과 테스트에 반영해 달라고 요청했다.
- AI 응답: Unicode 16의 분리 규칙을 그대로 사용하되, 문자를 속성 조합별 기호로 바꾼 뒤 글자 묶음 하나마다 한 글자로 계산하는 규칙을 만들었다. 생성 규칙에 인증 UID, 본인 프로필의 닉네임·색상, 필드 및 타입, 서버 작성 시각, 초기 좋아요·댓글 수 0, 비어 있지 않은 300자 이하 본문을 검사하도록 연결했다. Unicode 데이터 파일의 해시를 고정한 생성 스크립트도 추가했다.
- 판단: 채택. UTF-16 기반 단순 상한은 보이는 300자 이하의 가족 이모지를 차단했고, Unicode 정규식 한 개로 처리하는 안은 에뮬레이터 정규식 길이 한도를 넘었다. 검증한 속성 치환을 사용하면 현재 앱의 Flutter 글자 수와 일치하는 판정을 내릴 수 있다. UTF-16 길이부터 확인해 길이 300 이하의 일반 본문에서는 추가 변환을 건너뛴다.

### 자동 검증 결과

- 최신 main `60f8dc2` 기준의 로컬 `feat/#16-firestore-post-rules`에서 검증했다.
- 후보 규칙은 에뮬레이터의 Unicode 16 공식 글자 분리 사례 1,093개, 추가 비교 사례 1,011개, Flutter 입력 24개와 그중 전송 본문 21개에서 기대와 일치했다.
- 통합 규칙은 Node.js 24.22.3 / Firebase CLI 15.36.0 / Java 25에서 `npm ci --offline` 후 `npm test`로 검증했다. 게시글 테스트 40개와 기존 프로필 테스트 23개가 모두 통과했다. 가족 이모지 299·300개 허용, 301개 거부와 결합 한글·국기·줄바꿈·빈 본문 검사를 포함한다.
- 생성 스크립트의 `--check`가 통과했고, 실제 규칙에 생성된 Unicode 치환이 에뮬레이터에서 먼저 검증한 치환과 일치했다. 로컬 Dart 3.13.4의 `String.trim()`이 공백으로 보는 문자 집합과 서버의 빈 본문 판정도 대조했다.
- 첫 검증 범위는 서버 규칙과 로컬 에뮬레이터다. Firestore 저장소의 요청 형식 및 재시도, 실제 규칙 배포는 후속 확인 항목이다.


### 2. Firestore 규칙 CI 연결

- 프롬프트: Firestore 규칙 테스트를 CI에 연결하고 로컬에서 확인하며, 서버의 300자 규칙을 선택한 이유를 설명하는지 점검해 달라고 요청했다.
- AI 응답: 기존 워크플로에 별도 Firestore rules 작업을 추가했다. Node.js 24.22.3, Firebase CLI 15.36.0, Java 25를 지정하고, tests/firestore에서 npm ci와 npm test를 실행한다. README에도 UTF-16 단순 상한과 큰 정규식을 제외한 이유를 적었다.
- 판단: 채택. Flutter 검사와 독립적으로 임시 데모 프로젝트의 에뮬레이터에만 연결해 규칙 실패를 별도 검사 결과로 확인한다.

### 자동 검증 결과

- 로컬 Windows 임시 환경에서 Node.js 24.22.3과 Java 25를 사용해 Firebase CLI 15.36.0을 설치하고 npm ci, npm test를 실행했다. 설치는 로컬 캐시를 썼고, 규칙 테스트 63개가 통과했다. 테스트에 사용한 규칙·설정·스크립트의 SHA-256이 작업 폴더와 일치했다.
- GitHub Actions의 Ubuntu 러너에서 실행한 결과는 PR 브랜치를 푸시한 뒤 확인한다.

### 3. 게시글 상세의 댓글 읽기 허용

- 프롬프트: 댓글 조회만 허용하고 쓰기를 차단한 채, 댓글이 없는 글도 상세가 열리는지 확인해 달라고 요청했다.
- AI 응답: 인증되어 있고 게시글 문서가 존재할 때 해당 댓글을 조회할 수 있게 했다. 댓글 생성·수정·삭제는 차단했다. 에뮬레이터 권한 테스트와 Flutter 상세 화면에 대한 위젯 테스트를 추가했다.
- 판단: 채택. 상세 화면은 본문을 가져온 뒤 댓글 목록도 읽는다. 빈 댓글 목록 요청까지 허용하면 서버 저장소를 연결할 때 댓글이 없는 글도 상세에서 열 수 있다.

### 자동 검증 결과

- 수정 전 규칙으로 새 회귀 테스트를 실행했을 때, 게시글 조회에 성공한 뒤 댓글 목록 요청에서 `permission-denied`가 발생했다.
- 수정 후 `npm test`로 에뮬레이터 규칙 테스트 70개가 통과했다. 인증된 사용자의 빈 댓글 목록·기존 댓글 조회, 미인증 상태와 원본 게시글이 없는 댓글의 조회 거부, 댓글 생성·수정·삭제 거부를 확인했다.
- Flutter 3.47.5에서 `flutter test --no-pub`로 106개가 통과하고 기존 1개가 건너뛰었다. 상세 위젯에서 댓글 목록이 비었을 때 본문과 `댓글 0`이 표시되는 경우를 확인했다. 실제 앱의 Firestore 저장소 연결은 #47 범위다.

### 실기기 연동 검증

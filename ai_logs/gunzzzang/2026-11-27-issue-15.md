### 1. 연결 복구를 알아채는 방법

- 프롬프트: Figma M14 "연결되면 자동으로 다시 불러와요"를 만족하는 연결 복구 감지 방법 비교 요청
- AI 응답: (1) `connectivity_plus`로 기기 연결 변화를 받음 — 바로 알 수 있지만 새 패키지와 `pubspec.lock` 갱신이 필요하고, 와이파이 연결이 서버 연결을 보장하지 않음. (2) 오프라인일 때만 10초마다 같은 조회를 다시 보냄 — 패키지 없이 실제로 서버에 닿는지로 판단하고, `tester.pump(시간)`으로 검사 가능. 복구 인지가 최대 10초 늦음
- 판단: (2) 채택. 다시 시도 버튼으로 바로 확인할 수 있어 지연을 보완함. 피드는 새로고침, 상세는 글·댓글 재조회를 같은 간격(`offlineRetryInterval`)으로 씀

### 2. 피드 오프라인 표시

- 프롬프트: 저장소의 `PostPage.fromCache`를 #62 피드에 연결하는 방법 요청
- AI 응답: 캐시 페이지를 받으면 오프라인 배너(M1)를 띄우고 다시 조회를 예약. 서버 페이지를 다시 받으면 재연결 스낵바(M2)를 띄우고, 새 글은 기존 새 글 칩으로만 알려 목록과 위치를 유지. 처음부터 캐시가 비어 있으면 빈 피드로 오해하지 않게 기존 불러오지 못함 안내를 씀
- 판단: 채택. 배너를 목록 위에 두려고 기존 `Stack`을 `Column` 안에 넣음. 새 메서드로 빼지 않아 #71과 겹치는 범위를 줄임

### 3. 상세 오프라인 표시

- 프롬프트: 상세에서 저장된 본문만 보여주고 댓글 조회·입력을 막는 방법 요청
- AI 응답: `getComments`의 `OfflineException`만 따로 받아 댓글을 null로 두고, 배너(M14)·댓글 자리 안내·입력칸 비활성(`CommentInput.enabled`)을 표시. 다시 불러오는 동안 `FutureBuilder`가 이전 결과를 유지하도록 로딩 조건을 바꿈. 비동기 작업 뒤 화면이 닫혔으면 타이머를 만들지 않음
- 판단: 채택. 댓글 수는 목록 대신 저장된 글의 `commentCount`를 표시

### 직접 검증한 내용·결과

- CI 1차: 상세 자동 재조회 테스트 실패. `setState(() => _data = _load(...))`가 대입한 Future를 반환해 Flutter가 거부함 → 중괄호 본문으로 수정
- CI 2차: analyze 문제 없음, Flutter 테스트 190개 통과(이번 화면 테스트 7개 포함)

### 1. Codex 리뷰 지적 3건 검토와 반영

- 프롬프트: #77에 달린 Codex 자동 리뷰 3건(다음 페이지 캐시 결과, 좋아요 조회 중 연결 끊김, 캐시에 없는 상세 글)이 실제 문제인지 코드와 대조하고 수정 방법 요청

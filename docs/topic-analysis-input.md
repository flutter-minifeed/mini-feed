# 직접 입력 태그와 본문의 주제 분석

## 명세 AI1·AI3·R14 변경분

분석에는 본문과 사용자가 직접 확정한 태그를 사용한다. 본문이 비어도 직접 태그가 있으면 분석할 수 있다. 게시 가능 여부는 기존 본문 조건을 따른다. 추천 후보를 눌러 추가한 태그는 다음 분석 입력에서 제외한다. 사용자가 같은 이름을 직접 입력한 경우에는 직접 입력 출처를 따른다.

분석용 문자열은 본문, 직접 태그의 최초 추가 순으로 공백 한 칸을 사이에 두고 조합한다. 각 부분을 소문자로 바꾸고 Python의 공백 규칙에 따라 연속 공백은 한 칸으로, 앞뒤 공백은 빈 문자열로 바꾼다. 태그 맨 앞에 연속된 `#`와 그 직후 공백은 제거한다. 빈 태그는 건너뛰고, 정리 후 같은 태그는 한 번만 넣는다. 본문 속 `#`는 유지한다. 저장·표시에는 작성 화면에서 확정한 원래 이름을 사용한다.

## 기술 보고서 3장 변경분

글 전체에 대한 8개 주제 점수를 한 번 구한다. 직접 태그마다 별도의 큰 태그를 지정하지 않는다. 두 글자 조각이 사전에 일치할 때만 벡터의 해당 위치를 1로 설정한다. 기준값 0.30, 추천 최대 3개, 동점일 때 사전의 라벨 순서를 적용하는 규칙은 #27을 따른다.

| 분석 입력 | 사전 일치 수 | 여행 점수 | 추천 |
| --- | ---: | ---: | --- |
| 오늘 게임 정말 재밌었다. | 13 | 0.0023 | 취미 |
| 오늘 게임 정말 재밌었다. 제주여행 | 17 | 0.0681 | 취미 |
| 제주여행 | 2 | 0.8932 | 여행 |
| 쀍쀍 | 0 | 0.2294 | 없음 |

위 수치는 합성 예문을 앱에 포함된 모델에 넣어 Python으로 계산했다. 짧은 태그는 사전에 걸리는 조각이 적어 같은 태그도 함께 쓴 본문에 따라 추천 여부가 달라진다. 사전에 일치하는 조각이 없으면 모델 편향으로 점수가 나와도 후보를 비운다.

기준값을 재생성하려면 NumPy와 `ai-edge-litert`가 설치된 Python에서 저장소 루트의 `python tests/ai/generate_topic_input_cases.py`를 실행한다. Dart 단위 검사는 `app/`에서 `flutter test test/ai/topic_analysis_input_test.dart`로 실행한다. 기기 모델 점수는 #27의 `topic_tagger_device_test.dart`에 `topic_input_cases.json`을 Base64로 인코딩한 `TOPIC_TAGGER_CASES`를 전달해 절대 오차 0.00001로 대조한다.

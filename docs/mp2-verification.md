## 실행 준비

- 피드 동기화는 [PR #62](https://github.com/flutter-minifeed/mini-feed/pull/62)가 `main`에 머지된 커밋에서 검증한다. 오프라인 읽기와 재연결은 [#15](https://github.com/flutter-minifeed/mini-feed/issues/15)가 반영된 커밋에서 검증한다.
- Flutter 3.47.5 stable과 Dart 3.13.4를 사용한다. USB로 연결한 기기 A·B에 같은 커밋의 앱을 설치하고, 같은 팀 Firebase 프로젝트를 사용한다. 실행 절차는 [README](../README.md)를 따른다.
- 작성·동기화·콘솔 기록을 대조할 수 있도록 두 기기에서 식별하기 쉬운 테스트 본문을 정한다. 본문에는 개인정보를 넣지 않는다.

## 실기기 검증

| 점검 항목 | 절차 및 예상 결과 | 실제 결과 | 증거 |
| --- | --- | --- | --- |
| 익명 인증 | 두 기기에서 앱을 실행한다. 이메일·전화번호 입력 없이 피드에 진입하고, Firebase에서 두 기기가 서로 다른 익명 사용자로 인증됐는지 확인한다. | 미실행 | — |
| 작성 및 서버 기록 | A에서 테스트 본문을 입력해 게시한다. 저장 성공 뒤 피드에 새 글이 표시되고, Firestore 콘솔에 같은 본문과 서버 작성 시각이 기록된다. | 미실행 | A 작성 화면, 콘솔 기록 |
| 두 기기 동기화 | A가 게시하기 전에 B에서 피드를 열어 둔다. A에서 게시한 뒤 B에서 당겨서 새로고침하면 같은 글이 표시된다. | 미실행 | B 동기화 화면 |
| 게시 실패 | 글쓰기에서 테스트 본문을 입력하고 네트워크를 끊은 뒤 게시한다. 앱이 종료되지 않고 실패 안내가 표시되며 입력한 본문이 유지된다. | 미실행 | 오프라인 상태의 작성 실패 안내 화면(필수), 본문 유지 기록·로그 |
| 오프라인 읽기·재연결 | 온라인에서 읽은 글을 연결이 끊긴 상태에서 피드와 상세에서 다시 확인한다. 연결을 복구한 뒤 새로고침이 동작한다. | 미실행 | 오프라인·재연결 화면, 로그 |

#17의 검증 범위는 T01~T08, T14, T28, T30 중 MP2 범위, T32, T33이다. [테스트 케이스 원문](https://app.notion.com/p/40a8d812628a8147ad06c29535a12b10)과 대조한 뒤 각 케이스의 실제 결과와 증거를 기록한다.

기존 [PR #68 실서버 검증 기록](https://github.com/flutter-minifeed/mini-feed/pull/68#issuecomment-7094227440)에는 S25 Ultra 한 대의 게시, 상세 조회, 앱 재실행 후 재조회 결과가 있다. 이 표의 두 기기 동기화 결과와 증거는 위 절차로 확보한다.

## ANT 제출용 MP2 평가 기준

2026-11-25 ANT 2108 MP2 과제 화면에서 확인한 [평가 기준 다섯 항목](mp2.md#평가-기준)을 판정한다. README 소제목을 확정할 때는 ANT 과제 안내에서 별도로 참조하는 `확인 방법` 견본을 확인한다.

- [ ] 기기 A에서 작성한 글이 기기 B의 당겨서 새로고침 후 표시된다.
- [ ] 익명 인증만 사용하고 이메일·전화번호 등 개인정보를 수집하는 코드가 없다.
- [ ] 작성 실패 시 앱이 종료되지 않고 실패 안내를 표시한다. #17 검증 결과에는 본문 유지 여부도 기록한다.
- [ ] 설정 키를 하드코딩하지 않았고 제출물에는 설정 키 이름만 적은 `.env.example`을 넣었다.
- [ ] README에 Firebase 선택 이유, 익명 인증 방식, 백엔드 설정, 실행 절차, 확인 방법이 있다.

## `README.md`와 제출 ZIP 점검

- [ ] README의 `실행 절차`에 실행 명령 코드 블록, Flutter 3.47.5 stable / Dart 3.13.4, 검증 기기 모델을 적는다.
- [ ] README의 `확인 방법`을 MP2 실서버 동작에 맞춰 갱신한다. 현재 README에는 MP1 더미 데이터 확인 절차가 들어 있다. ANT 과제 안내의 짧은 평가 기준 이름을 `###` 소제목에 그대로 쓰고 각 항목 아래에 `조작`, `기대 결과`, `스크린샷`을 한 줄씩 적는다. 절 끝에는 시험 데이터와 온라인·오프라인 조건을 적는다.
- [ ] 제출 캡처는 A 작성, B 동기화, Firestore 콘솔 데이터, 오프라인 상태의 작성 실패 안내를 각 한 장 이상 포함한다. PNG/JPG에 `01_`부터 순서대로 번호를 붙이고 총 12장 이하, 한 장당 2MB 이하로 맞춘다. README의 `스크린샷` 줄에 파일명을 적을 때는 `screenshots/` 안의 실제 파일명만 쓰고 여러 장은 쉼표로 구분한다.
- [ ] ZIP을 열었을 때 최상위에 `app/`, `README.md`, `.env.example`, `screenshots/`가 바로 보이는지 확인한다. `app/pubspec.lock`과 `app/android/gradle/wrapper/gradle-wrapper.properties`가 들어 있는지 확인한다.
- [ ] ZIP에서 실제 `.env`, `docs/`, 설치·빌드 디렉터리(`build/`, `node_modules/`, `.gradle/`, `.dart_tool/`, `Pods/`, `DerivedData/` 등), base64로 인코딩된 생성 파일과 제출에 불필요한 대용량 자산을 제외한다.
- [ ] 앱 입력·캡처·로그에 실명, 연락처, 실제 인물 사진 등 개인정보가 없는지 확인한다. 소스·커밋 이력과 제출물에 실제 API 키나 비밀번호가 없는지도 점검한다.
- [ ] [#6](https://github.com/flutter-minifeed/mini-feed/issues/6)과 대조해 `ai_logs/`의 MP2 AI 사용 기록을 확인한다. `prompts_log.md`는 ANT 선택 항목이고, 팀은 [MP2 완료 기준](mp2.md)에 따라 기록을 `ai_logs/`에 보관한다.

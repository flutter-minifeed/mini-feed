# MP1 완료 기준

과제 페이지의 MP1 기준을 옮겨 적은 문서예요. 기준이 바뀌면 과제 페이지를 따르고 이 문서도 함께 고쳐요.

2026-11-17 운영 측 개정 공지에 따라 평가 기준(3개 → 5개)과 제출 규칙을 고쳤어요. 이미 제출했더라도 개정 기준으로 보완해 다시 제출해요.

## 단계 목표

SNS 앱의 얼굴인 피드를 만드는 단계예요. 더미 데이터로 게시글 목록(닉네임·작성 시각·내용), 글쓰기 화면, 게시글 상세 화면을 구현해요. 서버는 아직 없어요. 스크롤이 자연스러운 피드 UI와 작성 흐름에 집중하고, MP2의 서버 동기화는 이 화면 위에 올라가요.

- 예상 소요시간: 약 6시간
- 기술 스택: Flutter / React Native / Android 네이티브 / iOS 네이티브 중 1종. 후속 단계도 같은 스택을 이어서 써요.

## MVP

더미 게시글 10개가 스크롤 피드로 표시되고, 새 글을 작성하면 피드 최상단에 나타나며, 게시글을 탭하면 상세 화면으로 이동하는 상태

## 학습 목표

- 게시글 카드(닉네임·작성 시각·내용)로 구성된 스크롤 피드 구현
- 글쓰기 화면에서 작성한 글을 피드 최상단에 추가
- 게시글 탭 시 상세 화면으로 이동
- 작성 시각을 '5분 전' 같은 상대 시간으로 표시

## 평가 기준

다음 5가지를 모두 충족하면 통과예요.

1. 피드·글쓰기·상세 화면과 화면 간 이동이 동작한다.
2. 새 글이 피드 최상단에 추가된다.
3. 작성 시각이 상대 시간으로 표시된다.
4. README.md에 화면 구성·더미 데이터 구조·확인 방법·실행 절차 절(제목)이 있다. 더미 데이터 구조 절에는 데이터 자체가 아니라 필드 설명과 데이터 파일 위치를 적는다.
5. 더미 데이터(README에 파일 위치 명시)와 스크린샷에 실명·연락처·실제 인물 사진이 없고 민감정보가 제출물에 없다.

평가 결과 화면에는 기준이 짧은 이름으로 표시돼요(공지 예시: 필수 제출물, README 필수 절, 피드·글쓰기·상세와 더미 데이터, 게시글 카드·스크롤 …). README 확인 방법의 `###` 소제목은 이 이름과 같아야 해요. 전체 이름 목록은 과제 안내의 확인 방법 견본에서 확인해요.

## 평가 방식

- 필수 파일과 민감정보는 자동으로 검사해요. AI가 참고 점수를 제안할 수 있고, 최종 점수는 강사가 정해요.
- 검수자는 README의 실행 절차와 확인 방법대로 앱을 실행해요. 두 절이 없거나 부실하면 실행 동작 항목이 미확인으로 남을 수 있어요.

## 제출

완성한 프로젝트 소스코드를 ZIP으로 압축해 제출해요. 제출 후 관리자가 검토해요. 실제 키가 든 `.env` 파일과 `node_modules`·`build` 같은 설치·빌드 폴더는 ZIP에 넣지 않아요.

ZIP을 열었을 때 아래 항목이 바로 보여야 해요. 필수 항목이 빠지면 평가가 진행되지 않을 수 있어요. 이 문서가 있는 `docs/`는 제출 항목이 아니라서 ZIP에서 빼요.

| 항목 | 필수 | 내용 |
| --- | --- | --- |
| `app/` | 필수 | 피드 앱 소스 전체(더미 데이터 파일 포함 — 위치는 README '더미 데이터 구조' 절에 명시). 빌드 산출물(`build/`, `node_modules/`, `.gradle/`, `.dart_tool/`, `Pods/`, `DerivedData/` 등)과 base64로 인코딩된 생성 파일·대용량 자산은 ZIP에서 빼요. |
| `README.md` | 필수 | 화면 구성, 더미 데이터 구조와 파일 위치, 실행 절차, 확인 방법 |
| `screenshots/` | 필수 | 피드·글쓰기·상세 화면 각 1장 이상. 화면 순서대로 `01_`, `02_` 번호를 붙인 PNG/JPG, 최대 12장, 한 장 2MB 이하 |
| `prompts_log.md` | 선택 | AI 사용에 쓴 주요 프롬프트와 AI 응답의 채택/수정 내역. 내지 않아도 다른 항목 평가는 막히지 않아요. |

```
제출.zip
├── app/
├── README.md
├── screenshots/
└── prompts_log.md
```

### README 작성 규칙

- **실행 절차** 절: 실행 명령(코드 블록), 프레임워크/SDK 버전, 실행 기기(에뮬레이터 이름·API 또는 실기기 모델)를 적어요.
- **확인 방법** 절: 기준 이름을 `###` 소제목으로 쓰고, 그 아래 `- 조작:` · `- 기대 결과:` · `- 스크린샷:` 세 줄을 적어요. 절 끝에 시험 데이터와 네트워크 조건(온라인/비행기 모드)을 적어요.
- `스크린샷:` 줄에는 `screenshots/` 안의 파일 이름만 적고, 여러 장은 쉼표로 구분해요. 적은 이름은 실제 파일과 같아야 하고, 한 장을 여러 기준에 적어도 돼요.

```markdown
## 확인 방법

### 게시글 카드·스크롤

- 조작: 앱을 실행하고 게시글 목록을 아래로 스크롤한다
- 기대 결과: 게시글 카드가 목록에 표시되고 스크롤하면 다음 카드가 보인다
- 스크린샷: 01_feed.png

시험 데이터: app/assets/dummy/post/posts.json
네트워크: 불필요
```

### 버전·잠금 파일

- Flutter **3.47.5 stable / Dart 3.13.4**로 만들어요. 다른 버전이면 평가가 보류될 수 있어요.
- 잠금 파일 `app/pubspec.lock`과 `app/android/gradle/wrapper/gradle-wrapper.properties`를 함께 내요. 없으면 실행 확인이 늦어지거나 강사 확인으로 넘어갈 수 있어요.
- `gradlew`·`gradle-wrapper.jar`는 빼도 돼요(평가 서버가 채워요).

### 다시 제출하기 전 체크리스트

- [ ] README에 실행 절차 절(실행 명령 코드 블록, SDK 버전, 실행 기기)이 있다
- [ ] README에 확인 방법 절이 있고, 기준 이름 `###` 소제목 아래 조작·기대 결과·스크린샷 줄이 있다
- [ ] 확인 방법 끝에 시험 데이터와 네트워크 조건을 적었다
- [ ] Flutter 3.47.5 / Dart 3.13.4로 만들었다
- [ ] 잠금 파일을 넣었다
- [ ] ZIP에 `build/`, `.gradle/`, `.dart_tool/` 같은 빌드 산출물이 없다
- [ ] 스크린샷은 `01_`, `02_` 순서 이름, 12장 이하, 한 장 2MB 이하다
- [ ] 앱 데이터·스크린샷에 실명·연락처·실제 인물 사진이 없다
- [ ] API 키·비밀번호가 소스와 커밋 이력에 없다

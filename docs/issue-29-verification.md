# #29 주제 추천 검증

검사 범위는 앱에 포함된 모델과 태그 추천 함수다. PR #61의 `85a9427`에서 실행했고, 병합 커밋 `b3a58f4`와 비교해 `app/`의 추적 파일이 동일한 것을 확인했다. 앱 버전은 `1.0.0+1`이다.

## 입력과 판정 기준

검사용으로 작성한 합성 입력 9개를 Python과 Dart에서 비교했다. 빈 문자열·공백·한 글자·사전에 없는 이모지에서는 추천이 없었다. 점심 국수는 ‘음식’, 도서관 시험 공부는 ‘공부’, 대소문자와 공백이 섞인 입력은 ‘공부’, 반복한 달리기는 ‘운동·건강’, 과제와 영화와 저녁을 함께 언급한 문장은 ‘취미’로 분류됐다.

각 입력에서 글자 조각 집합, 8,192칸 벡터, 일치 특성 수, 최종 태그를 비교한다. 8개 모델 출력은 Python에서 가중치와 편향을 이용해 계산한 기준값과 각각 절대오차 0.00001 이내인지 검사한다. [기준값 9개](../app/integration_test/issue29_fixture.dart) · [Android 검사 코드](../app/integration_test/issue29_device_test.dart)

## 실행 방법

Android 기기를 USB로 연결하고 비행기 모드를 켠 뒤 Wi-Fi를 끈다. 저장소의 Android 앱 설정을 준비하고 `app/`에서 다음을 실행한다.

```sh
flutter pub get --enforce-lockfile
flutter devices
flutter test --no-pub --reporter expanded integration_test/issue29_device_test.dart -d <기기_ID>
```

모델은 한 번 로드한다. 0벡터로 첫 호출 1회와 후속 10회를 측정한다. 시간에는 Dart에서 네이티브 모델을 호출해 점수를 돌려받는 과정이 포함된다. Android 15(API 35) 가상 기기에서는 9개가 통과했고 모델 로드는 189.788ms, 첫 호출은 114.824ms, 후속 10회는 12.832~46.738ms였다.

## 글쓰기와 태그 저장 교차 검사 · 2026-11-24

선행 PR 두 개의 커밋을 각각 검사했다. [#73](https://github.com/flutter-minifeed/mini-feed/pull/73)의 `7023077`은 본문·직접 입력 태그를 분석하는 화면이고, [#72](https://github.com/flutter-minifeed/mini-feed/pull/72)의 `45ebf0d`는 태그 6개 이상을 게시하는 변경이다.

| 대상 | 확인한 결과 |
| --- | --- |
| #73 분석 입력 | 팀 기준 입력 7개의 본문과 직접 입력 태그를 Python에서 독립적으로 정규화해 조각·벡터 위치·추천 태그를 비교했다. 56개 점수의 최대 절대오차는 약 0.000000060으로 허용치 0.00001 이내였다. 모델과 사전은 11월 21일 검사한 파일과 바이트 단위로 일치했다. |
| #73 글쓰기 회귀 검사 | Flutter 정적 분석 통과. 단위·위젯 테스트 176개 통과, 1개 건너뜀. 키보드가 닫힐 때 변경된 입력만 분석하고, 추천 태그 선택으로 재분석하지 않으며, 직접 입력한 태그는 분석에 반영하는 동작을 포함한다. |
| #73 본문 처리 경로 | `WriteScreen`이 본문과 직접 입력한 태그를 결합하면 `TopicAnalysisController`가 분석을 요청한다. 네이티브 구현은 앱에 포함된 사전과 모델을 읽고 Dart isolate 안에서 점수를 계산한다. 이 경로에 외부 AI 요청은 없다. |
| #72 게시·조회 회귀 검사 | Flutter 정적 분석 통과. 단위·위젯 테스트 158개 통과, 1개 건너뜀. 로컬 Firestore 보안 규칙 96개와 저장소 검사 14개 통과. 페이지 조회 검사 1개는 처음 Chrome 연결이 끊겨 시작하지 못했고, 같은 커밋·새 에뮬레이터에서 단독 재실행해 통과했다. |

### Galaxy Note10 5G에서 확인한 화면

Android 12(API 31), USB, 디버그 빌드에서 실행했다. 테스트가 한글 문장을 입력하고 삼성폰의 실제 키보드를 열고 닫았다. 사람이 한 글자씩 한글을 조합하며 입력한 속도는 측정하지 않았다.

| 조건 | 실제 결과 |
| --- | --- |
| #73 비행기 모드·Wi-Fi 꺼짐 | 팀 태그 입력 7개와 자체 합성 입력 9개가 실제 기기 전처리·모델 점수·추천 비교를 통과했다. |
| #73 글쓰기 | ‘도서관에서 내일 시험 공부를 했어’를 입력하는 동안 점수는 숨겨졌다. 키보드를 닫자 분석 1회(25.281ms), ‘공부’ 추천과 실제 모델 점수 8개가 표시됐다. 같은 본문으로 키보드를 다시 열고 닫거나 ‘공부’ 추천을 선택했을 때 각각 추가 분석은 0회였다. 직접 태그 ‘달리기’를 추가한 뒤 키보드를 닫자 변경된 입력으로 1회(42.188ms) 분석했다. 시간은 첫 화면 검사에서 분석 함수가 결과를 돌려주기까지 측정한 값이다. [8개 점수](screenshots/issue-29/pr73_scores.png) · [직접 태그 반영](screenshots/issue-29/pr73_manual_tag.png) |
| #73 AI 사전 로드 실패 | 검사에서 존재하지 않는 사전을 읽도록 하자 ‘주제를 분석하지 못했어요.’가 표시됐다. 본문과 게시 버튼이 유지됐다. 같은 조건으로 재실행해 게시 버튼을 누른 뒤, 메모리 저장소에서 입력한 본문을 다시 읽어 일치함을 확인했다. 정상 추천 화면에서는 선택한 ‘공부’와 직접 추가한 ‘달리기’가 함께 저장됐다. [실기기 오류 화면](screenshots/issue-29/pr73_missing_dictionary.png) |
| #72 태그 6개 게시·재조회 | 글쓰기에서 6개 태그가 두 줄에 배치됐다. USB로 연결한 로컬 Auth·Firestore에 게시한 뒤 서버 원문에서 태그 6개와 문서 필드 8개를 확인했다. 점수·미선택 후보 필드는 없었다. 피드와 상세에도 같은 태그 6개가 표시됐다. [글쓰기](screenshots/issue-29/pr72_compose_six.png) · [피드](screenshots/issue-29/pr72_feed_six.png) · [상세](screenshots/issue-29/pr72_detail_six.png) |

이슈의 Figma 화면과 대조한 항목은 키보드를 닫은 뒤의 8개 점수와 태그 칩의 줄바꿈이다. 점수 판정에는 Figma의 예시 숫자 대신 실제 모델의 출력을 사용했다. 점수 막대 전환은 코드에 200ms로 설정돼 있다. 정지 캡처로 기기의 프레임 시간을 측정할 수는 없다.

마지막 실기기 실행 로그를 발췌했다. 종료 후 비행기 모드 꺼짐, Wi-Fi 켜짐, USB 연결 중 화면 켜짐 설정 원복을 확인했다.

```text
[#29] PASS native IME, eight scores, repeat=0 extra, recommendation=0 extra, manual=1 extra
[#29] PASS missing dictionary, error message, draft retained and published to local memory
[#29] PASS six tags; compose rows=2; local server document, feed and detail matched
```

## 남은 검증

- 합쳐진 앱에서 추천을 골라 직접 태그와 함께 게시한 뒤 서버·피드·상세에 최종 선택만 남는지 한 번에 확인한다. 분석 중·추천 없음·시간 초과 화면은 #28의 확정 시안과 대조한다. 실제 한글 조합 중 입력 끊김과 동일 점수 애니메이션 반복 여부도 최종 기기 확인 대상으로 남긴다.
- 팀의 모델·데이터 출처 안내는 [README](../README.md)에 있다. 데이터셋의 정식 명칭과 개별 이용 조건을 원출처와 대조하고 최종 제출 압축본의 구성도 확인한다.
